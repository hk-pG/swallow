# デスクトップの外観テーマ

最終更新: 2026-11-12  
対象: `apps/desktop` の見た目を、あとから差し替えられるようにする設計。この文書は設計だけであり、実装は別 PR に分ける。

関連: [#78](https://github.com/hk-pG/swallow/issues/78)（Apple HIG の試験適用。オープンのまま、この設計では採用しない）、[#87](https://github.com/hk-pG/swallow/issues/87)（セマンティックトークン。クローズ済み）、[#89](https://github.com/hk-pG/swallow/issues/89)（HIG 試作の撤去。クローズ済み）。この文書は Issue をクローズしない。

## 目的

Swallow のデスクトップで、外観を簡単に切り替えられるようにする。既定テーマはおよそ三つ。各テーマはライトとダークを持つ。OS の外観に従う選択も置く。

守る決定:

- Apple HIG 風の見た目（#78）は後回しにする。三つの既定テーマに HIG は入れない。`--hig-*` や `apple-hig` の試作は戻さない（#89 で撤去済み）。
- テーマとトークンはコンポーネントから分離する。コンポーネントはセマンティック変数だけを使い、テーマ名や light/dark を知らない。見た目の変更はトークンの値の差し替えで足りるようにする。

## 1. いまのスタイル

### 仕組み

Tailwind、CSS Modules、CSS-in-JS は無い。Vite が読む素の CSS で、入口は `apps/desktop/src/app/main.tsx` が次を順に import する。

| ファイル                                                                                         | 役割             |
| ------------------------------------------------------------------------------------------------ | ---------------- |
| `apps/desktop/src/styles/tokens.css`                                                             | 変数の定義       |
| `controls.css` / `layout.css` / `sidebar.css` / `items.css` / `inspector.css` / `quick-look.css` | 領域ごとのクラス |

ルールの正本は `apps/desktop/src/styles/README.md` とリポジトリの `AGENTS.md`「スタイル／デザイントークン」。色・余白・角丸・フォント・影・blur は `tokens.css` のセマンティック変数を参照する。`features/` と `app/` に見た目の直書きをしない。テーマ切替の仕組みは、いまのディレクトリには無い。

境界は `scripts/ci/style-token-boundaries.mjs`（`pnpm test` に含まれる）が検査する。

- `tokens.css` 以外の CSS に `#rgb` や `rgb()` / `hsl()` / `oklch()` が無いこと
- `features/` と `app/` の TSX に生の色、および色・余白・角丸・影などを直書きした `style={{ ... }}` が無いこと

検査が許すもの: CSS 内の生の `px`、`color-mix()`、システム色キーワード、`packages/shared` と `apps/extension` の色。

### トークン（`tokens.css` の `:root`）

色はほぼシステム色と `color-mix` で、固定のパレットは少ない。

| 種類           | 変数                                                              | いまの値                                     |
| -------------- | ----------------------------------------------------------------- | -------------------------------------------- |
| 文字           | `--color-label` / `--color-surface-text`                          | `CanvasText`                                 |
| 弱い文字       | `--color-secondary-label`、別名 `--muted`                         | `currentColor` を 55%                        |
| 面             | `--color-surface`                                                 | `Canvas`                                     |
| サイドバー     | `--sidebar-bg`                                                    | `currentColor` 4% を `canvas` に混ぜる       |
| 塗り           | `--color-fill` / `--color-fill-subtle` / `--color-fill-emphasis`  | `currentColor` を 8% / 6% / 15%              |
| アクセント     | `--color-tint`                                                    | `Highlight`（OS の選択色）                   |
| アクセント派生 | `--color-tint-subtle` / `muted` / `focus` / `ring` / `star`       | `Highlight` と `currentColor` の `color-mix` |
| 危険           | `--color-danger`                                                  | `#d33`                                       |
| 危険の文字     | `--color-danger-text`                                             | `#c0392b` を `currentColor` と混ぜる         |
| 星             | `--color-star`                                                    | `#f5b400`                                    |
| 区切り         | `--border` / `--color-separator`                                  | `currentColor` 15%                           |
| 強い区切り     | `--border-strong` / `--color-separator-strong` / `--shell-border` | `currentColor` 26%                           |
| 余白           | `--space-1` … `--space-5`                                         | 4 / 8 / 12 / 16 / 24 px                      |
| 角丸           | `--radius-sm` / `md` / `lg` / `pill`                              | 4 / 6 / 8 px / 999px                         |
| 文字サイズ     | `--font-caption` / `--font-body` / `--font-title`                 | 11 / 13 / 15 px                              |

`:root` は `color-scheme: light dark`。フォントは `system-ui` 系。影と blur の変数は無い。

### ダークモードは「OS 任せ」だけある

切り替える UI は無い。`prefers-color-scheme` のルールも無い。設定の `appearance` にテーマ項目は無い。

`color-scheme: light dark` だと、WebView は OS のライト/ダークに合わせて `Canvas` / `CanvasText` / `Highlight` を解決する。`currentColor` 由来の塗りと区切りは、その文字色に追従する。だから OS をダークにすると、シェルは暗い地面と明るい文字になる。

これは設計されたダークテーマではない。

- 危険色 `#d33` と星 `#f5b400` は両モードで同じ。暗い地面では星が強く、危険色のコントラストもモードごとに変わらない。
- アクセントは OS の `Highlight` なので、macOS と Linux の WebKit で色が揃わない。
- Quick Look のスクリムと影は `black` を混ぜている（`quick-look.css`）。ダークでも黒のまま。
- コンポーネント側の `color-mix(in srgb, currentColor …)`（ホバー、ドラッグ中の枠、サムネの地）は比率が CSS に固定で、テーマごとに変えられない。

### 直書きが残っている場所

色の `#` は、デスクトップ CSS では `tokens.css` の三色だけ（`#d33`、`#c0392b`、`#f5b400`）。クラス側の色は変数か `color-mix`。

余白と角丸の変数はあるが、クラス側は生の `px` が多い。`docs/desktop-ui.md` は 8px 刻みへの揃えを求めている。検査は色だけで、`px` は止めない。

角丸で変数を使っていない例:

- `items.css` のサムネ地 `border-radius: 4px`（`--radius-sm` と同じ値）
- `sidebar.css` の入力とタグ `border-radius: 4px`
- `quick-look.css` のパネル `border-radius: 12px`（`--radius-lg` の 8px より大きい。変数が無い）
- カラーラベルの丸は `50%`。形であり、テーマの角丸ではない

余白で尺度に無い例: `2px`、`5px`、`6px`、`10px`、`14px`。`12px` や `8px` も、値は `--space-*` と同じなのにリテラルの箇所がある（インスペクタの `padding: 12px`、ツールバーの `padding: 8px 12px` など）。

文字サイズも同様で、`11px` / `13px` / `15px` の変数がある一方、`sidebar.css` と `items.css` に `11px` と `12px` の直書きがある。`12px` と星の `18px` は変数が無い。

レイアウト用の幅（サイドバー `220px`、インスペクタ `280px`、サムネの `--item-thumb-size`）はテーマの余白ではない。動的な `left` / `top` とサムネ用 CSS 変数は、いまの例外のままにする。

影はトークンになっていない。例: メニューの `0 8px 24px`、Quick Look の `0 16px 48px`。

### 色のうちテーマに入れないもの

アイテムのカラーラベルはテーマではない。`packages/shared/src/color-label/colorLabel.ts` の `COLOR_LABEL_SWATCH` が 8 色の `#` を持ち、グリッドとピッカーが `style` で塗る。境界検査は、識別子経由の値と `--swatch` のようなカスタムプロパティを直書きとみなさない。ラベル色は素材の属性なので、テーマを変えても動かさない。

### 設定の置き場

外観の保存は既にある。Tauri の `app_config_dir()/settings.json`（`apps/desktop/src-tauri/src/commands/settings.rs`）。型は `packages/shared/src/settings/settings.ts` の `AppearanceSettings` と、Rust の `domain/settings.rs` が対になる。

いまの項目は `itemViewMode` と `thumbnailSizeIndex` だけ。フロントの `useAppearanceSettings` もこの二つだけを読む。Rust の `appearance` は未知キーを `extra` に残す。テストが `"theme": "dark"` をマージできることを見ているが、製品のテーマ項目ではない。専用の設定画面は無い。ビュー切替はツールバー（`LibraryToolbar`）にある。

#89 の試作は `localStorage` の `swallow.uiTrial` を使っていた。外観の正本には戻さない。

### 拡張

`apps/extension/public/popup.css` はデスクトップの CSS を import しない。同じ考え方（`color-scheme: light dark`、`Canvas` / `CanvasText` / `Highlight`）を独自に書き、エラー色 `#c0392b` とボタンの `HighlightText` を持つ。余白と角丸（`4px` / `6px` / `8px`）も直書き。

## 2. 他製品と、採る考え

Swallow に必要なのは「コンポーネントがセマンティック名だけを見て、名前の値が light/dark とテーマで入れ替わる」こと。シンタックスハイライト用の色層、テーマの配布ストア、数百個の UI 部品色は要らない。

### VS Code

テーマは名前付きのワークベンチ色（サイドバー、タブ、枠など、役割ごとの色）の集まり。シンタックスのトークン色は別層。ユーザー設定 `workbench.colorTheme` にテーマ名を保存する。`window.autoDetectColorScheme` が OS を見て、ライト用とダーク用に別々の「好みのテーマ」へ切り替える。ハイコントラストも別枠。上書きは `workbench.colorCustomizations` で、色 ID に対して行う。

採るもの: コンポーネント名ではなく役割の色 ID。設定にテーマの ID を保存する。OS 追従は「解決結果」であり、保存するのはユーザーの選択。

今回はやらないもの: ワークベンチ色の細目、シンタックス色、拡張機能としてのテーマ、ハイコントラスト（後述の判断まで）。

### Obsidian

UI は CSS 変数。コミュニティテーマは変数を上書きし、セレクタの詳細度は低く保つ。色は `.theme-light` と `.theme-dark` に書き、フォントなど共通のものは `body` に書く。設定の Appearance で、ベースのカラースキーム（ライト/ダーク）と、テーマを別々に選ぶ。一つのテーマが両方のスキームを出せる。

採るもの: 一つのテーマが同じ変数名を light と dark の両方で定義する。コンポーネントはクラス名の入れ子に依存しない。モードはルートの属性で切り替える。

今回はやらないもの: 任意のセレクタを上書きするコミュニティ CSS。Vault ごとのテーマ。

### Raycast

既定は OS の外観に従う。切ると、入れたテーマを一つに固定できる。ライト用とダーク用に別テーマを割り当てることもできる。Theme Studio は背景、主文字、補助色という少ない面を編集する。テーマはライト用かダーク用かのどちらかで、ペアはユーザーが組む。

採るもの: 既定は OS に従う。強制ライトと強制ダークを用意する。作者が触る色は少なく、画面側の変数は多すぎないようにする。

今回はやらないもの: Theme Studio、グラデーション、コミュニティ配布、モードごとに別テーマ ID を持つモデル。依頼は「約三つのテーマが、それぞれ light と dark を持つ」なので、Obsidian と同じ「1 ID が両モードを持つ」にする。VS Code の preferred light/dark theme のような「モードごとに別 ID」は、必要になってから足す。

### shadcn/ui

CSS 変数を正本にする。`:root` がライト、`.dark` が同じ変数の上書き。コンポーネントは `background` と `foreground` の組（`primary` と `primary-foreground` など）を使う。Tailwind はその変数をユーティリティに写すだけ。角丸は基準の `--radius` から段を作る。色の表記は OKLCH が多い。切替はルートの class で、`defaultTheme="system"`。切替の瞬間は色の transition を止める。

採るもの: 面とその上の文字を組で持つ（少なくとも、単色で塗るアクセントと、浮いた面）。切替は `prefers-color-scheme` だけに頼らず、ルート属性で確定する。属性が変わる瞬間、色のアニメーションは走らせない。

今回はやらないもの: Tailwind の導入（Swallow は素の CSS と変数で揃えている）、`next-themes`（Tauri にハイドレーション不一致は無い）、チャート用の5色。

### Radix Colors

各色相が 12 段のスケールを持ち、ライト用・ダーク用・アルファ用が別にある。段の役割が決まっている。1–2 が地面、3–5 が部品の塗り、6–8 が枠、9–10 が単色、11–12 が文字。セマンティックな別名（`accent` など）がスケールを指す。ダークでは別名の向き先を変える。部品名（`CardBg`）は別名にしない。同じ段番号でも、ライトとダークは別の色である。

採るもの: コンポーネントは別名だけを見る。ホバー、選択、枠、薄い塗りは、テーマファイルの中で基調色から決める。オーバーレイにはアルファを使う。12 段すべてをコンポーネント API には出さない。Swallow の既存の fill / separator / tint の段で足りる。

今回はやらないもの: `@radix-ui/colors` の依存と、全色相の同梱。三テーマは手で書く。

### 採用する形（要約）

1. コンポーネントが使う名前は、いまのセマンティック変数を維持する（Obsidian / shadcn / #87）。
2. テーマファイルが、その名前へ具体色を入れる。light と dark は同じ名前の別の値（Obsidian / Radix の別名）。
3. ルートの `data-theme` と `data-appearance` で適用する（shadcn の class 切替に相当。二つの軸があるので data 属性にする）。
4. 保存するのはテーマ ID と、`system` / `light` / `dark`。OS 追従のときは実行時に appearance を解決する（VS Code / Raycast）。
5. 既定は OS に従う（Raycast）。
6. 基調色はテーマごとに少数。派生はテーマファイル内の `color-mix` か、コントラストが足りないときだけ単色で上書きする（Radix の段、shadcn の組）。

## 3. 設計

### トークンの層

コンポーネントから見えるのは中段だけ。

| 層             | 誰が使う               | 中身                                                                                |
| -------------- | ---------------------- | ----------------------------------------------------------------------------------- |
| 基調           | テーマファイルの中だけ | 地面、文字、アクセント、危険、星。コンポーネントは参照しない                        |
| セマンティック | クラス CSS             | いまの `--color-*` / `--space-*` / `--radius-*` / `--font-*` と、足りない少数の追加 |
| コンポーネント | TSX のクラス           | 変数とクラスのみ。テーマ名を書かない                                                |

基調色を `--palette-*` のような名前で `:root` に漏らさない。テーマファイルの外から参照できないよう、各テーマのブロックの中でセマンティック変数へ直接代入する。

非色（余白、角丸、フォント）はテーマに含めない。三テーマは色だけが違う。角丸やフォントまでテーマごとに変えると、コンポーネントの密度がテーマ依存になる。#78 を後で採用するときも、色の値の差し替えで試せるようにしておく。

### セマンティック名

既存の名前を公開 API として残す。リネームは見た目の切替と同時にしない。

そのまま使う:

- 文字: `--color-label`、`--color-secondary-label`（別名 `--muted`）
- 面: `--color-surface`、`--color-surface-text`、`--sidebar-bg`
- 塗り: `--color-fill`、`--color-fill-subtle`、`--color-fill-emphasis`
- アクセント: `--color-tint` と既存の `subtle` / `muted` / `focus` / `ring` / `star`
- 危険: `--color-danger`、`--color-danger-muted`、`--color-danger-text`
- 星: `--color-star`
- 区切り: `--border`、`--border-strong`、`--color-separator`、`--color-separator-strong`、`--shell-border`
- 尺度: `--space-1` … `--space-5`、`--radius-sm` / `md` / `lg` / `pill`、`--font-caption` / `body` / `title`

テーマが正しく塗るために足す名前（初回の実装 PR で追加する）:

| 変数                                         | 用途                                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `--color-elevated` / `--color-elevated-text` | メニュー、Quick Look のパネル。地面より一段上げる。いまは `--color-surface` を流用している |
| `--color-overlay`                            | Quick Look のスクリム。`black` の直書きをやめる                                            |
| `--shadow-float` / `--shadow-overlay`        | メニューと Quick Look の影                                                                 |
| `--radius-xl`                                | Quick Look の `12px`。色のテーマとは独立                                                   |

単色アクセントの上に載せる文字（`--color-tint-text`）は、デスクトップの現行 UI にはほぼ要らない。選択行は `--color-tint-muted` の薄い塗りで、文字は `--color-label` のままである。拡張ポップアップのボタンだけが `Highlight` / `HighlightText` の組になっている。デスクトップに単色のアクセントボタンを足す段で `--color-tint-text` を追加する。先に空の変数だけ増やすことはしない。

選択の薄い塗りは、どのテーマでも「ラベル文字が読める洗い」に保つ。アクセント単色を選択背景にしない。

`color-scheme` はテーマの appearance ブロックが `light` か `dark` の一方を書く。いまの `light dark` の併記は、明示テーマとスクロールバーやネイティブ部品が食い違うので、属性が付いたあとは使わない。

### テーマファイル

正本は CSS。JSON から CSS を生成する段は置かない。色の二重管理を避ける。

置き場所の案:

```text
apps/desktop/src/styles/tokens.css          非色と、属性が付く前のフォールバック
apps/desktop/src/styles/themes/ink.css
apps/desktop/src/styles/themes/paper.css
apps/desktop/src/styles/themes/slate.css
apps/desktop/src/styles/themes/index.css    三ファイルの import だけ
```

各テーマは二つのブロックを持つ。

```css
[data-theme="ink"][data-appearance="light"] {
  color-scheme: light;
  --color-surface: #f5f5f7;
  --color-label: #1c1c1e;
  --color-tint: #0a84ff;
  --color-fill: color-mix(in srgb, var(--color-label) 8%, transparent);
  /* ほかのセマンティック変数 */
}

[data-theme="ink"][data-appearance="dark"] {
  color-scheme: dark;
  --color-surface: #1c1c1e;
  --color-label: #f2f2f7;
  --color-tint: #409cff;
  /* … */
}
```

ID は英小文字の固定文字列。表示名は日本語。スイッチャー用の一覧は TypeScript の定数（id、表示名、説明）にし、色そのものは持たない。色の正本は CSS のまま。

`scripts/ci/style-token-boundaries.mjs` の許可は `tokens.css` に加え `styles/themes/*.css` だけにする。それ以外の CSS に色リテラルを増やさない。テーマファイルの中の `color-mix` は許す。クラス CSS に残っている `color-mix(currentColor)` と `black` は、対応するセマンティック変数へ移す（移行の PR で触る範囲をその置換に限る）。

属性が付く前の一瞬は、`tokens.css` にインクの色を置き、`@media (prefers-color-scheme: dark)` を `:root:not([data-appearance])` に限ってダーク側を出す。JS が属性を付けたあとは、メディアクエリではなく属性が勝つ。

### light / dark / system の解決

保存する値:

| フィールド               | 型                                  | 既定の案   |
| ------------------------ | ----------------------------------- | ---------- |
| `appearance.themeId`     | `"ink"` \| `"paper"` \| `"slate"`   | `"ink"`    |
| `appearance.colorScheme` | `"system"` \| `"light"` \| `"dark"` | `"system"` |

解決:

1. `colorScheme` が `light` または `dark` なら、それを `data-appearance` にする。
2. `system` なら `window.matchMedia("(prefers-color-scheme: dark)")` を見る。ダークなら `dark`、そうでなければ `light`。変化を `change` で購読し、`system` のあいだだけ属性を更新する。
3. `themeId` が未知、または将来テーマを消したあとの値なら `ink` に戻す。
4. `document.documentElement` に `data-theme` と `data-appearance` を付ける。付ける直前に、ルートの `transition` を一時的に無効にする（色がフェードしてチラつくのを避ける）。

保存するのは選択だけである。解決後の light/dark は書かない。OS を変えたときに `system` が追従するため。

設定の読み込みは `invoke` なので、最初の描画は CSS のフォールバック（インク + OS）になる。ユーザーが紙やスレートを保存していても、設定が返るまでインクが一度出る。v1 はこれを受け入れる。`localStorage` に前回のテーマをキャッシュして先に塗る方法は、#89 でやめた二重の正本に戻るので、既定では置かない。

適用の置き場は、設定 feature が値を読み、アプリの起動時に `documentElement` へ反映する小さい関数。アイテムやフォルダの feature はテーマを知らない。

### スイッチャーと保存先

保存先は既存の `settings.json`（`get_settings` / `update_settings`）。`AppearanceSettings` に上の二フィールドを、shared の型と Rust の構造体の両方へ追加する。camelCase はほかの設定と同じ。未知キー用の `extra` は残す。

`SETTINGS_VERSION` は 1 のままにする案。フィールドは optional で、欠けるファイルは既定（インク + system）として読む。バージョンを上げる移行処理は、この二フィールドだけでは要らない。

UI の案: 専用の設定画面はまだ無いので、ツールバーのビュー切替の近くに「表示」を置く。

- 外観: システム / ライト / ダーク
- テーマ: インク / 紙 / スレート（名前と、地面・アクセントの小さな見本）

選択は即 `update_settings` する。ビューモードと同じく、失敗時はコンソールへ出し、画面の属性は楽観的に更新してよいかは実装時に既存の `useAppearanceSettings` に揃える。

設定画面が別 Issue で入ったら、同じフィールドをそこへ移し、ツールバーには入口だけ残してよい。コマンドパレットは無いので、新規には作らない。

### 三つの既定テーマ（方向）

共通: フォントは `system-ui` のまま。余白と角丸は共通トークン。選択は薄いアクセント。危険と星は「状態の色」で、アクセント色相には寄せない。

### 拡張とトークンの共有

v1 では共有しない。デスクトップの切替を、拡張のポップアップに依存させない。#87 のスコープ外と同じく、拡張への即時展開はしない。#12 は拡張を別リポジトリにする予定なので、いま CSS を強く結合しない。

共有したくなったときの契約は次だけで足りる。

- セマンティック変数の名前（この文書の一覧）
- インクの light/dark の値

拡張の `popup.css` は `public/` の静的ファイルで、Vite の CSS エントリではない。共有するなら `packages/shared` にインクの CSS を置き、デスクトップが import し、拡張のビルドがそのファイルを popup 用 CSS として出す。テーマ ID の切替や `settings.json` はデスクトップ専用のままにする。拡張は OS 追従のインクだけでよい。

カラーラベルの `#` は既に `@swallow/shared` にある。テーマ CSS とは混ぜない。

### リスク

- **OS 差が消える。** `Canvas` / `Highlight` をやめると、OS のアクセント色や純白の地面とは一致しなくなる。代わりに OS 間で同じ色になる。これは意図したトレードオフである。
- **最初のフレーム。** 保存済みテーマがインクでないとき、設定の `invoke` が返るまでインクが出る。
- **クラス側の `color-mix`。** テーマファイルだけを差し替えても、コンポーネントに残った比率は変わらない。B と C で変数へ移す。移し忘れると、テーマごとにホバーの濃さが揃わない。
- **ネイティブの `<select>`。** `sidebar.css` のコメントどおり、`option` の背景は不透明である必要がある。`--color-surface` は不透明な単色にする。`color-mix` の結果を option に渡さない。
- **コントラスト。** 紙のテラコッタと、ダークの星は、提案値のままでは足りない可能性がある。E の受け入れに「ラベルと危険と星を画面で見る」を入れる。
- **カラーラベルをテーマ色で塗ってしまう。** ラベルは素材の属性。アクセントや危険色へ寄せると、テーマを変えたときにタグの意味が変わる。
- **スクロールバーとフォーム部品。** `color-scheme` を appearance ごとに単一へしないと、ダークテーマで明るいスクロールバーが残る。
- **設定の片側だけ更新する。** shared と Rust がずれると CI の既存テストとシリアライズが壊れる。D は両方とテストを同じ PR に入れる。
- **並行作業。** ドラッグ移動の作業と `layout.css` / `items.css` が衝突しうる。テーマ側の差分を色の置換に限る。
- **HIG をテーマの一つとして再導入する。** #78 は後回し。HIG を試すときは、コンポーネントを書き換えず、第四のテーマファイルかインクの値の差し替えで見る。試作トグルと `localStorage` は使わない。
- **ハイコントラスト。** VS Code には別テーマがある。Swallow の v1 には入れない。`forced-colors` は対象外。

## 4. 先生が決めること

実装の B 以降に進む前に、次を決める。

- 三つの方向（インク / 紙 / スレート）と、上の基調色を採用するか。差し替えるなら、名前と基調色（地面、文字、サイドバー、アクセント、危険、星）をライトとダークの両方で指定する。
- 既定を「インク + システム追従」にするか。
- アクセントをテーマごとの固定色にするか。OS の `Highlight` に合わせ続けるか。この設計は固定色を勧める。
- テーマは色だけ変え、余白・角丸・フォントは三テーマ共通のままでよいか。この設計は共通を勧める。
- スイッチャーをツールバーに置くか、設定画面ができるまで切替 UI を待つか。設定の保存（D のスキーマ）だけ先に置いてよいか。
- `SETTINGS_VERSION` を 1 のまま optional フィールドで足すか。この設計は 1 のままを勧める。
- 起動直後、保存済みテーマが一瞬インクになることを受け入れるか。`localStorage` の先行描画は置かない案である。
- カラーラベル 8 色はテーマと無関係の固定 `#` のままでよいか。この設計は固定を勧める。
- 拡張ポップアップを、デスクトップのテーマ切替に含めるか。この設計は含めず、名前の共有だけ後回しにする。
- ハイコントラスト、モードごとに別テーマ ID、ユーザーが色を編集する Theme Studio を、v1 の外でよいか。この設計は外にする。
- #78 の HIG を、この三テーマが終わるまで後回しのままでよいか。この設計はその前提である。
