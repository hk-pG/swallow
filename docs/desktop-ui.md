# Swallow デスクトップ UI 指針（サイドバー）

Eagle 比較（`docs/eagle-vs-swallow.md`）とは別に、実装の判断基準として使う。

## 基準にしたガイドライン

[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) の Layout と Sidebars を基準にする。デスクトップのソースリストに近く、次のルールをサイドバーに採用する。

- **8pt グリッド**に合わせる（Layout）。間隔は `--space-*` だけを使う
- サイドバーは **見出しと、同じ形の行**で組む（Sidebars）。作成は見出しの操作、編集は選択行の直下
- **同じ階層のラベルは同じ先頭位置**に揃える（Layout の整列）
- **階層は一定幅でインデント**する。幅は 8pt グリッドの 16px（`--tree-indent`）

折りたたみ（disclosure）はまだ無い。階層はインデントだけで示す。

## スペーシング（8px ベース）

| トークン | 値 | 用途 |
|---|---|---|
| `--space-1` | 4px | チップ内・コンパクトなギャップ |
| `--space-2` | 8px | 行・見出しの左右インセット、フォーム内ギャップ |
| `--space-3` | 12px | セクション内パディング、サイドバー内余白 |
| `--space-4` | 16px | セクション間の上マージン、フォルダ階層の字下げ（`--tree-indent`） |
| `--space-5` | 24px | 大きなブロック間（将来のシェル用） |

新規 UI はこの尺度に揃える。任意の `px` は例外理由を PR に書く。

## シェルとペインの区切り

- **主手段**: 1px の `var(--shell-border)`（通常の `var(--border)` よりコントラスト高め）
- **補助**: サイドバーは `var(--sidebar-bg)` で中央ペインと背景をわずかに分ける
- インスペクターは既存の左ボーダーを `var(--shell-border)` に揃える

## サイドバーの構造

Apple のサイドバーは「見出し + 同じ形の行」の繰り返しにする。色やフォントは変えず、置き場所だけをこの形に揃える。実装は `SidebarSection`。

1. **見出し** — タイトルと、作成するなら末尾に一つだけ「追加」。作成フォームは押したときだけ見出しの直下に出す。リストの上に常設しない
2. **行** — 移動先のラベル（`.nav-item`）。行の中にセレクトや削除を常設しない
3. **選択中の操作** — その行の直後に、一段下げた縦の並び（`.sidebar-detail`）。フォルダ、スマートフォルダ、タグで同じ位置
4. **階層** — 子ノードに `--tree-indent`（16px）を一度だけ足す

セクション間は上ボーダー + `padding-top` + `margin-top`（`--space-3` / `--space-4`）。ライブラリヘッダー直後の最初のセクション（ビュー）は上ボーダーなし。

## リスト行と密度

- ナビ行（`.nav-item`）: 上下左右とも `--space-2`（8px）。行間は `--space-1`（4px）
- セクション見出し（`.sidebar-section-header`）は行ラベルと同じく左右 `--space-2`
- `.sidebar-detail` の操作も行ラベルと同じ左右インセット。深さの字下げで padding を上書きしない

## 適用範囲（本 Issue）

- サイドバーと、その左右境界（中央・インスペクター）
- ツールバー・インスペクター内部の再設計は別 Issue
